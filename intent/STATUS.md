## 解除构建障碍

在本机普通 PowerShell 中运行（需要网络）：

```powershell
cd E:\WorkSpace\CodexCLI\codex-intent
powershell -NoProfile -ExecutionPolicy Bypass -File .\intent\Prepare-Build.ps1
```

`ExecutionPolicy` 仅作用于该子进程，不修改机器策略。脚本下载官方 rustup 安装器并核对 SHA256，将 `CARGO_HOME`、`RUSTUP_HOME`、构建产物放在本项目 `.intent-work` 内；不修改全局 PATH。然后依据本 worktree 的工具链文件安装组件并执行 `cargo fetch --locked`。失败直接退出，不删除锁文件、不换用较旧工具链。

为解决 Cargo 在 Windows 检出 libc++ 时的路径长度限制，构建脚本会选择空闲盘符，把 `.intent-work` 映射为短路径，并在 `.intent-work/build-drive.txt` 记录盘符。当前本机使用 `X:`。这是当前 Windows 登录会话中的目录别名，数据仍在项目中；重启后脚本会重新建立映射，遇到盘符被其他位置占用会停止。所有构建进程结束后，可用 `subst X: /D` 移除这个别名；先核对 `subst` 输出中的目标目录。依赖安装还复用上游工具验证 V8 和 ripgrep 的固定校验值。

`Build-Intent.ps1` 是完整候选包构建入口，按上游目录结构构建 CLI、执行服务、代码宿主和 Windows 沙箱辅助程序；默认使用上游 `dev-small` profile，也接受 `-Profile release`。它保留构建日志，校验编译版本与包元数据的一致性，产物标记为 `built-unvalidated`，不会切换安装。目前尚未成功产出候选包。

`Test-Intent.ps1` 为每次运行设置独立 `CODEX_HOME` 和固定终端能力；上游测试各自在 OS 临时目录创建隔离数据，避免继承本仓库的项目发现结果。脚本保存日志及失败报告，不发布或替换任何程序。测试报告必须对应开始和结束均干净的同一源码 commit，才能作为该候选的自动化验收证据。完整包和交互检查仍需另行通过。
